# Introduction

Relic is a web server framework for Dart, built by the [Serverpod](https://serverpod.dev) team. It grew out of [Shelf](https://pub.dev/packages/shelf), and it keeps Shelf's model of handlers that turn requests into responses and middleware that wraps handlers.

A Relic server is an ordinary Dart program. This one answers a GET request for `/` with a greeting:

Run it, ask it for `http://localhost:8080/`, and it answers `Hello, world!`. The [Hello world](./01-getting-started/02-hello-world-example.md) page builds on this program one step at a time.

## The pieces

The program above already shows most of what Relic is made of, and the reference pages take the pieces in turn.

A [handler](./02-reference/01-handlers.md) is a function that receives a `Request` and returns a result. Usually the result is a `Response`, but it can also upgrade the connection to a WebSocket, or take the connection over entirely. The [router](./02-reference/03-routing.md) picks a handler by the method and the path of the request, and a path can hold parameters, wildcards and tails. [Middleware](./02-reference/08-middleware.md) wraps the handlers below a path, to log, check credentials or change responses, and [context properties](./02-reference/02-context.md) carry what it learns to the handler. The [request](./02-reference/04-requests.md) gives a handler typed access to the URL, the query, the headers, the body and forms, and the [response](./02-reference/05-responses.md) and its [body](./02-reference/06-body.md) decide what goes back on the wire. [Headers](./02-reference/07-headers.md) are read and written through typed accessors, and a program can declare its own. [Static files](./02-reference/09-static-files.md) are served by a ready-made handler, and [hot reload](./02-reference/10-hot-reload.md) applies most changes without a restart.

## How Relic differs from Shelf

If you know Shelf, most of Relic will look familiar. These are the places where it works differently:

| Area | Shelf | Relic |
|------|-------|-------|
| Headers | Strings in a map | Typed accessors that validate values |
| Routing | `shelf_router`, which tries routes in order | A built-in router on a trie, matched segment by segment |
| WebSockets | The `shelf_web_socket` package | Built in |
| Path parameters | Strings, passed as extra handler arguments | Read from the request by symbol, with typed accessors |
| Static files | The `shelf_static` package | `StaticHandler`, with cache busting and ETags |
| Hijacking | A thrown `HijackException` | A returned `Hijack` or `WebSocketUpgrade` result |
| Request state | A `Map<String, Object>` context | Typed context properties |
| Body | Content and encoding set separately | One `Body` that carries content, type and encoding |

The [Migration from Shelf](./01-getting-started/03-shelf-migration.md) page goes through each of these with code.
